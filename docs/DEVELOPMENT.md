# Сборка и устройство проекта

## Сборка Windows-меню

`Build.ps1` использует штатный C#-компилятор .NET Framework в `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`. Он собирает меню, `ZoneSpawner.Setup.exe` и тестовый хост. Мастер ссылается на сборку меню, поэтому оба EXE должны оставаться рядом.

`src/SetupCore.cs` содержит поиск Steam/VDF, закреплённое скачивание, распаковку и установку с восстановлением после ошибки; `src/SetupForm.cs` — интерфейс и CLI, `src/SetupEntry.cs` — отдельная точка входа. В обычном меню этот код не запускается, новых игровых callback нет.

```powershell
./Build.ps1
./ZoneSpawner.Tests.exe $PWD.Path
```

Для сборки в другую папку:

```powershell
./Build.ps1 -OutputDirectory './build'
```

При запуске меню ищет каталоги рядом с EXE, поэтому одной копии EXE без JSON/TSV недостаточно. Тестовый хост из `build` можно запускать с путём к каталогу проекта.

## Нативный запуск вместе с игрой

Нужен x64 Tiny C Compiler, скачанный из источника проекта/доверенного дистрибутива. Компилятор не включён в репозиторий.

```powershell
./BuildNative.ps1 -TccDirectory 'D:\Tools\tcc'
```

`src/MenuLauncher.c` вызывает только Win32 `CreateProcessW` для соседнего EXE и передаёт PID игры. Lua `launcher.lua` вызывает библиотеку один раз при старте мода. WinForms проверяет путь владельца по локальному installation manifest и закрывается по событию завершения игры.

## Lua-проверки

Python 3.11+ и `lupa`:

```powershell
python -m pip install -r tests/requirements.txt
./Test.ps1
```

Проверяются протокол, количество/допуск ID/сессии, реальные обработчики WinForms, калибры, совместимость, отмена асинхронных чтений и 120 циклов простоя без новых вызовов игрового потока. `SetupTests.cs` проверяет вторичную/старую библиотеку Steam, некорректные manifest-пути, хеши, отмену, защиту существующего загрузчика, traversal ZIP и восстановление после ошибки записи manifest. Все изменения выполняются в собственной временной папке. Моки не заменяют проверку в самой игре.

Для 0.4.1 отдельно проверено настоящее HTTP-скачивание UE4SS и установка реальных закреплённых архивов в изолированную папку с тестовым EXE: все 37 установленных файлов совпали с manifest; DLL фикса и лицензии сохранены. GUI нашёл настоящую Steam-сборку и V1.2 в загрузках, заблокировав перезапись действующей установки. Запрос UAC не выполнялся в автоматической проверке.

## Архитектура

```text
WinForms EXE ↔ локальные файлы bridge ↔ UE4SS Lua ↔ функции игры
```

- `main.lua` проверяет маленькие файлы запросов; игровой поток вызывается только при действиях/проверке связи видимого меню.
- `protocol.lua` проверяет GUID, session token, время и whitelist ID; произвольная строка консоли не принимается.
- `inventory-job.lua` читает `CppMediator:GetItemsCountInInventory(Pawn, ItemName)` порциями до 16 ID / примерно 1 мс с интервалом 50 мс.
- `quest-job.lua` читает живой WorldMap открытого КПК, проверяет масштаб относительно игрока и поверхность через `K2_ComputeFloorDist`.
- `world.lua` обслуживает позицию, телепорт и создание существ. Команды не повторяются автоматически.
- `catalog-bridge.tsv` / `actors-bridge.tsv` содержат разрешённые ID и признак ограниченного прототипа.
- `Locations.cs` загружает локальный `locations.json` один раз; фильтры и карточки не читают игру. Телепорт использует прежний протокол и механизм возврата. [Извлечение координат и специализаций](LOCATIONS.md).

## Каталог и обновления игры

Каталог закреплён за одной сборкой: SHA-256 в `catalog-info.json`, `actors-info.json` и проверка EXE в установщике. Изменение версии требует повторного извлечения собственных локальных прототипов, сверки связей/локализации и проверки native API. Подмена одного хеша не обновляет данные.

Публичный каталог содержит параметры и идентификаторы, без полного текста игровых описаний. `tools/import_descriptions.py` восстанавливает описания локально. Изменённые этим инструментом описания не следует коммитить; runtime state и game files исключены `.gitignore`.

## Подготовка релиза

Собери EXE/DLL, прогони проверки, обнови CHANGELOG и SHA256SUMS. В пакет не включаются `bridge`, personal settings, `installed-manifest.json`, `config.lua`, логи, архивы игры/UE4SS/фикса и локально импортированные полные описания. Скриншоты в `docs/screenshots` сделаны с настоящего меню; снимки при закрытой игре подписаны соответствующим образом.
